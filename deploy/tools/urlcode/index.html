URLエンコード

文字列をパーセントエンコードし、また元に戻します。通常の方式と、フォーム送信で使われる「空白を + にする」方式の両方に対応しています。

変換の向き

フォーム方式は application/x-www-form-urlencoded に合わせ、空白を + として扱います。

変換はUTF-8として行います。Shift_JISなどで作られた文字列は正しく変換できません。

Ctrl（Macは⌘）+ Enter でも変換できます。

使い方

入力はブラウザ内で処理され、サーバーには送られません。

  1. 「変換の向き」でエンコードかデコードを選びます。ボタンの表示も選んだ向きに変わります。
  2. フォーム送信のデータを扱う場合は「フォーム方式」をオンにします。エンコードでは空白が + になり、デコードでは + が空白として戻ります。
  3. 「変換する文字列」欄に入力し、「エンコードする」（または「デコードする」）を押します。Ctrl（Macは⌘）+ Enter でも実行できます。
  4. 結果を確認し、「結果をコピー」でクリップボードに入れます。デコードで % の後ろが不正な場合は、理由が赤字で表示されます。

URLエンコードについて

URLでは、そのままでは使えない文字を「%」と2桁の16進数で表します。これをパーセントエンコードといいます。日本語のような文字は、まずUTF-8のバイト列に変換し、その1バイトずつを %XX の形にします。たとえば「日」は UTF-8 で E6 97 A5 なので、%E6%97%A5 になります。この道具はブラウザの encodeURIComponent と decodeURIComponent を使い、同じ規則で変換します。

通常方式とフォーム方式の違い

encodeURIComponent は、英数字と - _ . ! ~ * ' ( ) をそのまま残し、それ以外を %XX にします。空白は %20 です。一方、HTMLのフォーム送信で使われる application/x-www-form-urlencoded では、空白を + で表し、! ' ( ) ~ も %XX にします。この道具の「フォーム方式」はこの規則に合わせています。クエリ文字列のなかでは + が空白を意味しますが、URLのパス部分では + は文字どおりのプラスです。フォーム方式はフォームのデータにだけ使ってください。

エラーになる例

デコードでは、% の後ろに2桁の16進数がないとエラーになります。また、16進数としては正しくても、UTF-8として不正なバイト列（例: %FF の単独）はデコードできません。% そのものを文字として含めたいときは、あらかじめ %25 にエンコードされている必要があります。すでにエンコード済みの文字列をもう一度エンコードすると、% が %25 になり、二重エンコードになります。元の文字列がUTF-8かどうかも確認してください。
